Contributing to Aetheris

First of all, thank you for your interest in contributing to Aetheris Raut Scanner!

Aetheris is an open-source Rust-based network reconnaissance and port scanning project developed under Seleste Technologies.

We welcome developers, security researchers, Rust enthusiasts, and open-source contributors who want to help improve the project.

Getting Started

Before contributing:

1. Fork the Aetheris repository.
2. Clone your fork to your local machine.
3. Create a new branch for your changes.
4. Make your modifications.
5. Test your changes before submitting a pull request.

Example:

git clone https://github.com/seleste3580-dev/Aetheris.git
cd Aetheris
git checkout -b feature/your-feature-name

How to Contribute

You can contribute in several ways:

- Improving scanning performance.
- Developing new scanning capabilities.
- Fixing bugs and errors.
- Improving documentation.
- Optimizing Rust code.
- Improving CLI usability.
- Adding tests.
- Suggesting architectural improvements.

Reporting Bugs

When reporting a bug, please include:

- A clear description of the problem.
- Steps to reproduce the issue.
- Expected behavior.
- Actual behavior.
- Operating system and Rust version.
- Relevant error messages or logs.

Please avoid including sensitive information such as private IP addresses, credentials, or network configuration details.

Suggesting Features

Feature suggestions are welcome!

When proposing a feature, explain:

- What the feature does.
- Why it would be useful.
- How it could improve Aetheris.
- Any implementation ideas you may have.

Code Guidelines

To maintain code quality, contributors should:

- Follow standard Rust conventions.
- Write clean, readable, and maintainable code.
- Use meaningful variable and function names.
- Add comments where necessary.
- Handle errors properly.
- Avoid unnecessary dependencies.
- Include tests for new functionality where practical.

Before submitting changes, run:

cargo fmt
cargo check
cargo test

Pull Request Guidelines

When submitting a pull request:

1. Ensure your branch is up to date.
2. Provide a descriptive pull request title.
3. Explain what you changed and why.
4. Include relevant test results.
5. Link related issues where applicable.
6. Keep pull requests focused on specific improvements.

Pull requests will be reviewed before being merged.

Security Guidelines

Aetheris is intended for legitimate network administration, security research, and authorized security testing.

Contributors must:

- Respect network ownership and authorization.
- Avoid introducing malicious functionality.
- Never use the project to access systems without permission.
- Report security vulnerabilities responsibly rather than publicly disclosing exploitable details.

Community Standards

All contributors are expected to:

- Be respectful and professional.
- Welcome constructive feedback.
- Avoid harassment and discrimination.
- Focus discussions on improving the project.
